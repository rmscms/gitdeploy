Deploy

Deploy Workflows: Safe, Fast, and Observable

The Deploy stack is built around one principle: always know what is changing, where it is going, and what happened after upload.

Primary Deploy Pipeline

Step 1 - Repository Readiness

  • Checks uncommitted state and branch context.
  • Guides commit or compare action when needed.
  • Surface push-needed state clearly before deploy.

Step 2 - Compare & Select

  • Diff source and target branch snapshots.
  • Select exactly which files should be deployed.
  • Avoid accidental uploads from unrelated changes.

Step 3 - Upload & Verify

  • Upload progress and per-operation logs are visible.
  • Warnings identify partial or risky outcomes.
  • Status is persisted into project history records.

Step 4 - Post-Deploy Sync

  • Follow-up merge/push actions can be triggered.
  • Keeps repository and remote state aligned.
  • Reduces drift between local and production branches.

Remote Editor Workspace

What It Adds

  • Browse remote tree and open files directly.
  • Multi-tab editing for hotfix scenarios.
  • Dirty-state indicators before upload.
  • Upload progress + post-upload feedback.

Safety Behavior

  • Prompt when closing unsaved tabs.
  • Fallback editor if advanced host is unavailable.
  • Timeout-aware open flow for laggy servers.
  • Connection recovery hooks for transient failures.

FTP Explorer & Direct Upload

For rapid operational tasks, Direct Upload and FTP Explorer remain first-class workspaces. They are ideal for emergency fixes, mapped uploads, and selective remote file operations.

  • Direct Upload: map local folders to remote paths, upload with progress, and keep rollback-ready context.
  • FTP Explorer: inspect remote structure, include hidden files when needed, and manage conflict-aware downloads.
  • Cross-page consistency: shared remote path resolution logic minimizes mismatched upload destinations.
Recommended flow: Compare -> Select -> Deploy -> Verify logs -> Sync branch state.
