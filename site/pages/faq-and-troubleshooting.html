FAQ and Troubleshooting

Common questions and fast answers for release operators, backend engineers, and deployment maintainers.

Frequently Asked Questions

Why is my release ZIP suddenly much larger?

A self-contained publish includes .NET runtime binaries. Use framework-dependent publish when you need a smaller archive.

Why is the first remote editor open slower?

The initial editor host can require warm-up. Recent versions preload editor runtime and moved stat checks to background for faster first open.

Can I re-run backup validation manually?

Yes. Use history actions to trigger import/validation with the original schedule configuration.

How do I avoid deploying ignored files?

Use compare/select workflow and sync-only options where available, then verify deploy logs before promotion.

Troubleshooting Playbook

Connection and Transfer Issues

  • Validate connection profile and remote root path.
  • Retry from refresh/connect controls before restarting app.
  • Review operation log for timeout or permission hints.

Editor Behavior

  • If advanced editor host fails, fallback mode should activate.
  • Use close prompts to avoid losing unsaved tabs.
  • Check open timing logs to isolate download vs editor delays.

Build and Packaging

  • Close running app process before full publish/build copy step.
  • Use compile target if executable lock blocks copy stage.
  • Confirm version bump in project file before tagging.

Database Import Problems

  • Check server packet limits for large SQL imports.
  • Inspect validation stage output to pinpoint failure step.
  • Use process list view during long-running operations.

Escalation Notes

When filing an issue, include: app version, target environment, exact action sequence, and the last relevant lines from operation logs. This dramatically reduces troubleshooting time.
